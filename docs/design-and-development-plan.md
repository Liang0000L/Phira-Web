# Phira Web 静态网页设计与开发计划

## 1. 项目目标

在当前空仓库中实现一个可直接由静态文件托管的 Phira 网页客户端。通过浏览器调用 Phira 服务端 API，提供谱面发现、谱面详情、下载、浏览器游玩、用户登录、收藏夹管理和谱面排行榜。界面以简体中文为主，采用克制、清晰、适合长时间浏览的视觉风格。

本项目是独立网页移植，不代表 TeamFlos 官方产品。除谱面数据本身（谱面包内的曲绘、音频等）外，不使用 Phira 官方 Logo、字体、角色、插画、图标或其他品牌素材；界面图标、排版和装饰均由本项目自行实现。

## 2. 设计方向

- 视觉基调：低调、优雅、轻量；以近白和石墨色为底，辅以克制的青绿色强调色，避免仿制原生客户端的视觉资产。
- 信息架构：桌面端采用紧凑侧栏与主内容区；移动端收敛为顶部导航和单列内容。
- 主要页面：谱面库、谱面详情与游玩、收藏夹、排行榜、个人登录状态。
- 谱面卡片优先展示曲绘、曲名、作者、谱师、难度和评分；加载、空结果、无网络、鉴权失效和 API 错误均提供明确状态。
- 支持键盘焦点、语义化控件、可读对比度和减少动态效果偏好。

## 3. 技术与服务约束

- 交付物使用原生 HTML、CSS、JavaScript 模块，不依赖构建期服务端，不设置自有后端；静态托管即可部署。
- 主 API 使用 `https://phira.5wyxi.com`。实现统一请求层处理分页、JSON 错误和 `Authorization: Bearer <token>`。
- API 文档来源：<https://muimi.club/phira-api/>，此文档为基于客户端源码整理的非官方参考；实际行为以服务器为准。
- 浏览器跨域请求依赖 Phira API 服务端允许网页来源。开发阶段验证 CORS；若生产来源不被允许，纯静态网页无法绕过浏览器跨域限制，须由 API 服务方配置 CORS 或另行提供代理服务。
- 不将账号密码、令牌或成绩验证数据写入源码、URL、日志或遥测；登录令牌只保存在浏览器本地存储，并提供登出清除入口。生产部署须为 HTTPS。
- 静态文件链接来自 API 响应，不把下载后的谱面包提交进仓库。

## 4. 功能设计与 API 映射

### 谱面浏览与详情

- 调用 `GET /chart`，支持关键字、排序、难度区间、类型及分页；首屏展示常用筛选和谱面列表。
- 调用 `GET /chart/{id}` 获取完整详情、谱面文件、曲绘、预览音频及更新时间。
- 调用 `GET /chart/popular` 展示热门谱面；图片优先使用谱面 API 返回的曲绘。
- API 的分页响应为 `{ count, results }`。前端根据 `count` 显示分页状态并保留当前筛选。

### 下载与游玩

- 通过谱面详情中的 `file.url` 下载谱面包，处理下载进度、失败重试及文件名；下载地址是服务端返回值，不自行拼接未文档化路径。
- 开始游玩前解析谱面包，读取谱面元数据、音乐、插图和 note 时间轴。浏览器使用 Web Audio API 播放音乐并渲染可交互的游玩画面，适配鼠标、触控与键盘输入。
- 游玩页提供开始、暂停、继续和结果状态；明确标记练习/离线状态，不把本地估算结果伪装成服务器认证成绩。
- 只有确认能生成与官方服务端协议兼容的验证 payload 后，才调用 `POST /play/upload`（请求包含 `chart`、`token`、`chartUpdated`）。否则保留本地结果，并清楚说明该局不能上传或进入线上排名。不得提交伪造 token。
- 对谱面格式解压/解析、音频解码和资源跨域失败提供可恢复错误提示；大文件避免阻塞主线程。

### 登录与用户

- 使用 `POST /login` 邮箱密码登录，提交 `email`、`password`、`clientVersion` 和 `clientFlavor`；成功后保存 `id`、`token`、`refreshToken`。
- 使用 `GET /me` 检查令牌并读取当前用户信息；`401` 时按文档尝试一次 `POST /login` refreshToken 刷新，再重放原请求。
- 登录表单不在 URL 中携带凭证；支持主动登出。注册暂不列入首版必要流程，避免扩大范围。

### 收藏夹

- Phira API 暴露的是云端收藏夹，而不是单独的谱面收藏开关。通过 `GET /collection`、`GET /collection/{id}` 读取收藏夹；登录后通过 `POST /collection` 新建收藏夹。
- 收藏操作将谱面加入或移出用户收藏夹，并以 `PATCH /collection/{id}` 的曲目列表形态同步；先读取当前版本，处理 `412` 冲突，不静默覆盖。
- 未登录时可使用本地收藏列表；登录后提供显式导入/同步操作，避免未经确认覆盖云端数据。

### 排行榜

- 谱面详情内调用 `GET /record/list15/{id}?std=false` 展示前 15 名；提供标准化分排序切换 `std=true`。
- 对成绩字段缺失、玩家信息不可用、空榜和请求错误进行容错显示。
- 可在当前用户视图调用 `GET /record/best/{id}` 查看该用户对应谱面的最佳成绩；不以本地练习分数替代服务端成绩。

## 5. 开发阶段

1. 初始化静态应用骨架、设计 token、响应式布局与路由状态。
2. 实现 API 请求层、错误提示、认证与令牌刷新。
3. 实现谱面列表、筛选分页、详情、下载及排行榜。
4. 实现本地练习游玩流程与可用的输入、音频、结果状态。
5. 实现本地收藏和云端收藏夹读取、编辑、同步及冲突处理。
6. 完成移动端、无障碍与失败状态检查，验证静态部署和实际 API 连通性。

## 6. 验收标准

- 网页可由静态文件服务器提供，不要求自有后端或运行时构建步骤。
- 谱面可检索、筛选、查看详情、下载；谱面详情可查看服务器排行榜。
- 用户可登录、恢复登录状态、登出；受保护 API 正确附带令牌。
- 未登录收藏和登录后的云端收藏夹工作流清晰，冲突不造成静默数据丢失。
- 用户能够在浏览器启动谱面练习并看到结果；只有实现并验证服务端接受的成绩验证格式后才启用成绩上传。
- 桌面和移动布局可用，加载、空态、离线、鉴权错误和 API 错误都有可理解反馈。
- 仓库不包含 Phira 官方非谱面素材、账号凭证、用户令牌或谱面包。

## 7. 风险与待验证项

- 需要确认 API 主机的浏览器 CORS 策略与真实部署域名；纯前端不能自行解除跨域限制。
- API 文档指出成绩上传 token 承载回放或验证数据，但未描述完整生成协议。必须查验上游开源客户端实现与服务端接受条件；在验证兼容前不提交成绩。
- 谱面包格式、渲染规则和不同谱面功能的浏览器兼容性须通过实际谱面验证；复杂或不支持的资源应显示明确错误，而不是伪称完整兼容。
- 收藏夹 API 有整体更新和并发时间戳语义，必须避免并发冲突时静默覆盖。
